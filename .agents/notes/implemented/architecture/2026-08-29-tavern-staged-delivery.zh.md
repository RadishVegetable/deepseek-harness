# Agent Note: 让 Tavern 从普通聊天渐进为剧情运行时

Status: implemented

[English](2026-08-29-tavern-staged-delivery.md) | 中文

## 问题

Tavern 需要一条可用的角色优先角色扮演循环，同时不能让后续连续性能力修改共享资源或引入按角色调用模型。分阶段设计必须在自动 Journey 更新对用户可见前，先确定归属和回放规则。

## 决策

Tavern 使用现有的持久化 Session 作为 Journey 存储。面向玩家的界面从主角色卡开始，把附属或选中的世界书作为支持上下文，并使用共享 conversation composer。`selectForSession` 在资源影响后续提示词前记录所选资源 ID；runtime 通过当前资源库解析这些 ID。

已交付的连续性层在 `people[personId]` 和 `world` 下保存自然语言事实。一次 GM 响应包含完整的 `story` 正文和可选的 `updates` 操作。Host 先持久化 assistant 响应，再追加接受或拒绝的 `tavern/fact` 记录，把活动事实投影到后续提示词，并保留原始响应供恢复。用户控件可以修正或撤销已有事实，但不会手动创建事实。

浏览器界面将资源库作者编辑和活动 Journey 分开。编辑可复用来源只影响未来选择，不会向活动 Journey 追加新的 baseline。世界书和世界人物详情把模型或回退方式整理的源栏目与 Journey 事实放在一起。整理结果作为独立的 `tavern/assets-normalized` 事件保存，不会改变导入源。

普通路径保持一次 GM 调用的规则，不创建规划器、角色专属 Agent 或发言者选择循环。每项扩展在成为默认依赖前，都必须说明用户可见的问题、持久化事件、模型或存储成本以及回放行为。

## 考虑过的替代方案

**先完整构建结构化领域模型。** 如果在真实故事证明价值前就要求关系、库存和其他 schema，会过早约束产品。自然语言 Journey 事实以更小的持久化词汇提供连续性。

**保留独立的角色聊天和世界故事模式。** 分离模式会重复入口、transcript 和继续生成语义。附属世界书让角色优先的 Journey 同时支持聚焦关系和大型设定。

**只把可变状态放在浏览器。** 浏览器状态无法在 reload 后重建提示词，也无法支持 Session 分支。追加式 Session 事件为 Host 提供一个可回放的归属点。

## 后果

首条产品路径仍是一条持久化聊天流，同时为资源选择、事实事件、上下文激活和 UI 投影确定了归属。导入来源保持可复用，Journey 事实在不同 Session 和分支前缀之间保持隔离。

系统还不提供角色卡或世界书作者编辑后的再次整理、丰富的 Journey 专属资源编辑、完整的 World Info 执行、按 observer 隔离的检索或真正的多 Agent 群聊。这些能力在改变默认路径前需要额外的事件词汇和成本决策。

## 验证

聚焦的 Host 和客户端测试覆盖资源选择、事实回放与召回、错误更新处理、分支和 Journey 隔离、每次玩家输入一次生成以及 Journey 事实修正。文档和持久化 catalog 包含事实事件和 Remote 词汇。
