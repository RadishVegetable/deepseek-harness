# Agent Note: Tavern Journey 按 ID 解析共享源资源

Status: implemented

[English](2026-09-02-tavern-source-asset-lifecycle.md) | 中文

## 问题

Tavern 资源库中的资源是可复用的源文档，而 Journey 日志保存的是持久化引用。阻止删除所有被引用的资源会妨碍替换导入文档，也会让归档状态控制本不相关的资源库操作。

## 决策

Tavern 选择事件只持久化角色卡和世界书 ID，以及可选的玩家身份。Journey runtime 需要资源时，通过当前持久化源注册表解析这些 ID。`deleteAsset` 从内存和持久化源注册表中删除资源，不扫描活动或归档 Session 日志。已有日志保持不变。重新导入相同 ID 会恢复解析；Journey 请求缺失 ID 时会报告所选资源不可用，直到源资源恢复。归档状态只控制历史投影，不固定资源库中的源记录。

## 考虑过的替代方案

**持久化 Journey 资源快照。** Journey 自有副本可以让旧对话在源资源删除后仍可读取，但会增加当前源资源引用模型之外的存储和版本语义。产品使用明确的源资源 ID，因此资源库替换和重新导入保持为直接操作。

**继续保护归档 Journey 的资源引用。** 这样可以保护冷回放，但代价是资源库无法删除和重新导入文档。产品选择通过导入相同 ID 提供明确的恢复路径。

**随源资源删除或改写 Journey 引用。** 改写持久化 Session 会修改用户历史，并让归档内容依赖资源库清理。Session 保留原始选择记录；缺失源资源则作为明确的可恢复失败处理。

## 后果

替换或重新导入源资源可能改变已有 ID Journey 解析到的资源内容。删除被选择的源资源可能暂时使 Journey 不可用；导入相同 ID 后即可恢复，而无需改写 Journey 日志。活动和归档 Journey 的资源引用都不会阻止源资源删除；持久化删除失败时，删除操作仍会恢复内存注册表。

## 验证

Host 集成测试删除被归档 Journey 引用的源资源，并验证重启后删除仍然持久化。现有选择测试继续覆盖只包含 ID 的 `tavern/assets-selected` 事件和源资源解析。
