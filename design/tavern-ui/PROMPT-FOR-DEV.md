# 前端开发任务提示词（可直接复制给开发者）

> 用法：把下面整段发给前端开发（或作为 ticket 描述）。设计参考文件路径需随项目位置调整。

## 任务：实现「酒馆 Tavern」前端 UI

### 一、背景

「酒馆 Tavern」是一个 AI 驱动的跑团 / 互动小说应用。玩家选一张「角色卡」+ 可选的「世界书」开始旅程，AI 扮演 GM 写剧情，玩家自然语言输入推进故事（一次输入 = 一段剧情）。故事推进中会沉淀出角色关系、世界观、秘密、物品等「记忆」，在右侧随时可查、可改。

**核心原则：这是「沉浸的故事空间」，不是 IDE、不是配置后台。**
- 第一屏用户看到的必须是：角色立绘 + 名字 + 当前场景 + 最新一段剧情。
- 故事舞台永远是视觉中心；技术控件（模型参数、Prompt、asset id 等）收进二级入口。
- 让玩家专注在"接下来发生了什么"，不要打断沉浸感。

### 二、设计参考（必须先看）

1. **高保真交互原型**：`design/tavern-ui/index.html`（浏览器打开，含全部页面、状态与可点交互，是最终验收基准）
2. **设计规范与验收清单**：`design/tavern-ui/DESIGN-SPEC.md`（token、交互规范、响应式、Checklist）
3. **视觉素材**：`design/tavern-ui/assets/`（角色立绘 ×2、场景图 ×1；正式环境替换为产品素材，但不得退回"首字母占位"）

### 三、需要实现的页面

| 页面 | 要点 |
|---|---|
| 入口页 | 三步流：①选角色卡（必选，卡片=立绘+名字+一句话简介）→ ②选世界书（可选，青色标识）→ ③玩家身份（昵称/人设）→「开始旅程」。无角色卡时提供「导入」卡（JSON/PNG 拖拽）。 |
| 旅程页（重点） | 左=故事舞台（场景 banner + 悬浮立绘卡 + 衬线剧情流 + 底部输入框）；右=「旅志」面板（见下）。 |
| 历史页 | 旅程列表（缩略图+标题+元信息），点击恢复。 |
| 诊断视图 | Prompt 检查器 / 上下文激活决策 / 模型参数 / 原始数据。**冷色调、视觉上与主流程隔离**，技术字段只出现在这里和设置抽屉。 |

**右侧「旅志」面板（核心新设计，必须按要求做）：**
- 角色信息与世界观**并行可看**（Tab 切换即可，不做互斥关闭）。
- 栏目化：每栏目=卡片，含若干「键—值」事实行。栏目**完全动态**：可增、可删、可改名、可排序（hover 浮现 ✎/🗑/⋮⋮ 操作，不做层层菜单）。
- 冲突警示：当 AI 新设定与已记录值矛盾，该栏目卡**红色描边+脉冲动画**，卡内裁决条提供「保留新值 / 抛弃」一键裁决，操作后即时反馈（Toast）。
- 事实编辑：行内编辑，Enter 保存 / Esc 取消，误删可撤销。
- 事实审计：面板头 🕮 图标打开抽屉，按时间列出所有记忆变更（**含被拒绝的变更及原因**）。

### 四、必须实现的交互与状态

- [ ] **流式生成态**：发送后出现「头像+三点跳动+GM 正在续写」指示器，正文逐字打出 + 铜色光标，期间发送按钮禁用。
- [ ] **空态 / 加载态 / 错误态**：与主视觉同一语言（骨架屏 shimmer / 插画式空态），错误提示"说人话"（发生了什么 + 如何恢复），禁止只弹"操作失败"。
- [ ] **窄屏折叠**：≤860px 右侧面板转为底部抽屉 + 右下悬浮按钮；触控目标 ≥44px。

### 五、视觉规范（必须遵守，直接复用原型 CSS 变量）

- 基调：暖色暗底（主背景 `#1a1510` 系），**非纯黑、非单色仪表盘**；全站一层 3.5% 噪点纹理。
- 三色点缀，语义严格一致：**铜 `#c99b64`=行动/主色，红 `#c95a43`=冲突/危险，青 `#57a89c`=世界书/次要**。
- 中文排版：剧情正文用衬线字体，`17px / line-height 2.0 / 两端对齐`，阅读列宽 ≤640px；段落间留白体现时间/地点/人物切换。
- 卡片只用于「重复项」（角色卡列表、右侧栏目块、审计条目）；页面主体不封框。
- 文案：界面文案用中文，不得残留英文占位（如 kicker）。

### 六、技术建议（不强约束）

- 从 `index.html` 的 `:root` 提取 CSS 变量为全局 token 文件（如 `design-tokens.css`）。
- 组件拆分参考：`CharacterCard / WorldCard / SectionCard / FactRow / ConflictBanner / Beat / Composer / Drawer / AuditItem / DiagnosticCard`。
- 数据模型建议：栏目 `{ id, name, items:[{key,value,version}] }`，冲突由 version 冲突检测触发。

### 七、验收（对照 `DESIGN-SPEC.md` 第 7 章）

交付时需逐项自检并勾选验收清单，重点：第一屏无 JSON/Prompt/asset id 泄露；角色与世界观可同时查看；栏目增删改名排序可用；冲突裁决即时反馈；流式生成效果；窄屏折叠；对比度满足 WCAG AA（正文 ≥4.5:1）。

### 八、交付格式

- 按项目现有技术栈实现（React 组件 + 样式方案遵循项目约定）。
- 交付时附：实现说明（哪些按原型做、哪些有偏差及原因）+ 验收清单勾选结果。
